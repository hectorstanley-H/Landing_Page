FAQ

Common questions

Do you support single-tenancy or on-premise deployment?

Our default is multi-tenant and for most enterprise customers, it is the right choice. Each customer has dedicated encryption keys, dedicated API keys, and strict logical isolation. SOC 2 Type I and II certified, ISO 27001 in audit.

For organizations with specific regulatory or data sovereignty requirements, we assess on-premise and private cloud deployment on a case by case basis. Our engineers will help you identify the right model during the first conversation.

What cloud providers do you support?

We run natively on AWS and can deploy directly into your own AWS tenant if your security or sovereignty requirements call for it.

Azure and GCP are supported but require additional implementation work. If your organization runs on one of these environments, our engineers will assess the right deployment path with you from the first conversation.

How do H agents connect to and interact with our existing systems?

Two integration paths, depending on what your systems expose.

If no API is available, H agents interact directly through the user interface, reading screens, navigating applications, and completing tasks the way a human operator would. This is the primary unlock for legacy systems, mainframes, and internal tools that were never designed for automation.

If an API exists, agents use standard integration patterns. No changes required to your existing stack.

In both cases, agents authenticate with standard Active Directory credentials and inherit exactly the read and write permissions you assign to that account. No admin rights. You define the scope.

How do you manage the confidentiality of data used by the models?

Four layers: encryption at rest and in transit, zero retention during inference, no training on your data, and tenant isolation with separate keys per customer.
